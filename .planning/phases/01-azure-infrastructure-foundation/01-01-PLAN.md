  <action>
    Create minimal Express 5 server following patterns from research:

    1. server/src/index.ts:
       - Import and configure helmet, cors
       - CORS origin should allow frontend URL (use env var FRONTEND_URL with fallback)
       - Mount health router at /api/health
       - Listen on PORT env var (default 3000)
       - Export app for testing

    2. server/src/routes/health.ts:
       - GET / returns JSON: { success: true, data: { status: "healthy", timestamp, version } }
       - Use API response shape from CLAUDE.md: { success: true, data: T }
       - Version from process.env.npm_package_version or "1.0.0"

    Per research: Express 5 has native async error handling, no need for express-async-errors.

    Test locally: npm run dev in server/, then curl http://localhost:3000/api/health
  </action>

<task type="auto">
  <name>Task 3: Create GitHub Actions deployment workflow</name>
  <files>
    .github/workflows/deploy.yml
  </files>
  <action>
    Create GitHub Actions workflow for Azure deployment using OIDC (not publish profile):

    1. Trigger: push to main branch

    2. Permissions: id-token: write, contents: read (required for OIDC)

    3. Environment: production (allows environment secrets)

    4. Steps:
       a. Checkout code
       b. Azure Login using OIDC:
          - uses: azure/login@v2
          - client-id, tenant-id, subscription-id from secrets
       c. Setup Node.js 22 with npm cache
       d. Install dependencies: npm ci
       e. Build: npm run build
       f. Deploy server to Azure App Service:
          - uses: azure/webapps-deploy@v3
          - app-name: bwwt-app (or use secret/var)
          - package: ./server/dist

    Per research: OIDC is preferred over publish profiles for security.

    Note: This creates the workflow. Actual deployment requires:
    - Azure App Service to exist (created via Azure CLI/Portal)
    - GitHub repository secrets configured
    - Federated credentials configured in Azure
  </action>
  <verify>
    .github/workflows/deploy.yml exists and is valid YAML
    Workflow references azure/login@v2 with OIDC pattern
  </verify>
  <done>
    GitHub Actions workflow file created with OIDC authentication pattern
  </done>
