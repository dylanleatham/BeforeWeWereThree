<objective>
Implement PIN-based authentication with JWT sessions and device fingerprinting for participant identification.

Purpose: This is the authentication gate for the entire application. Users must enter the correct PIN to access content. The system distinguishes between two participants (A and B) based on their device, enabling personalized experiences in later phases.

Output: Working PIN authentication flow where users enter a date-based PIN, receive a 30-day session, and are identified as Participant A, B, or read-only based on their device fingerprint.
</objective>

  <action>
    Create authentication infrastructure following research patterns:

    1. shared/types/api.ts - Standard API response types:
       - ApiResponse<T> = { success: true; data: T } | { success: false; error: ApiError }
       - ApiError = { code: string; message: string }

    2. shared/types/auth.ts - Auth-specific types with Zod:
       - pinSchema: 8 digits, valid MMDDYYYY format
       - ValidatePinRequest: { pin: string; deviceFingerprint: string }
       - SessionPayload: { participantId: string; role: 'guest' | 'admin'; deviceFingerprint: string }
       - Participant type matching Prisma model

    3. server/src/services/session.ts - JWT handling with jose:
       - createSession(participantId, role, fingerprint): returns JWT string
       - verifySession(token): returns SessionPayload or throws
       - Use HS256 algorithm, 30-day expiration per CONTEXT.md
       - Secret from process.env.JWT_SECRET

    4. server/src/services/participant.ts - Participant assignment:
       - getOrCreateParticipant(fingerprint, role): returns participantId
       - Admin role returns 'admin' (no participant distinction)
       - First guest device becomes 'A', second becomes 'B'
       - Third+ device becomes 'readonly' per CONTEXT.md
       - Uses db.participant queries

    5. server/src/db/queries/config.ts - Config queries:
       - getGuestPin(): returns stored guest PIN
       - getAdminPin(): returns stored admin PIN
       - setPin(key, value): sets PIN value
       - Queries app_config table

    6. server/src/middleware/auth.ts - JWT middleware:
       - Reads session cookie
       - Verifies JWT and attaches session to req
       - Returns 401 if invalid/expired

    7. server/src/middleware/rateLimit.ts - PIN rate limiting:
       - 5 attempts per 15 minutes per IP+fingerprint
       - Friendly error message per research

    Per research: Use jose (not jsonwebtoken). Cookie should be httpOnly, secure, sameSite strict.
  </action>
  <verify>
    npx tsc --noEmit passes
    shared/types exports are importable from server
    session.ts createSession returns a valid JWT string
  </verify>

    1. server/src/routes/auth.ts:
       POST /validate-pin:
         - Apply pinRateLimiter middleware
         - Validate request body with Zod validatePinRequestSchema
         - Check PIN against stored guest/admin PINs
         - If invalid: return 401 with { code: 'INVALID_PIN', message: "Hmm, that's not it. Try again?" }
         - If valid: call getOrCreateParticipant with fingerprint
         - Create session JWT
         - Set cookie: 'session', httpOnly, secure, sameSite strict, 30 days maxAge
         - Return { success: true, data: { role, participantId } }

       GET /session:
         - Apply auth middleware
         - Return current session info (role, participantId, designation)

       POST /logout (optional per CONTEXT.md - not required but useful for admin):
         - Clear session cookie
         - Return success

    2. Update server/src/index.ts:
       - Import and mount authRouter at /api/auth
