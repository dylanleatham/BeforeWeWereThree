<task type="auto">
  <name>Task 2: Create letter service with SignalR integration</name>
  <files>
    server/src/services/letter.ts
  </files>
  <action>
Create server/src/services/letter.ts following WYR service pattern:

1. getLetterState(envelopeId: string, participantId: string):
   - Gets prompt by envelope ID (return null if not found)
   - Gets my letter (may be null - not started)
   - Gets all submitted letters for prompt
   - Determines phase:
     - If my letter has submittedAt: 'waiting' or 'revealing' or 'complete'
     - If my letter is null or no submittedAt: 'writing'
   - If submitted count >= 2:
     - Build revealedLetters with mine and partner's
     - Phase is 'revealing' (or 'complete' if envelope completed)
   - Return LetterState object

2. saveLetter(envelopeId: string, participantId: string, content: string, photoUrl: string | null):
   - Get prompt by envelope ID
   - Call createOrUpdateLetter query
   - Return updated letter
   - No SignalR broadcast for save (silent auto-save)

3. submitLetter(envelopeId: string, participantId: string):
   - Use db.$transaction for atomicity (like WYR):
     a) Get prompt
     b) Get or create letter
     c) Set submittedAt if not already set
     d) Count submitted letters
   - After transaction:
     - Broadcast 'letterSubmitted' via SignalR to group `activity:${envelopeId}`
     - If count >= 2:
       - Get both letters
       - Mark envelope as 'completed'
       - Broadcast 'letterRevealReady' with both letters (relative to each participant)
   - Return { revealed: boolean, letters?: { mine, partner } }

4. SignalR message types (from shared/types/letter.ts):
   - LetterSubmittedMessage: { type: 'letterSubmitted', participantId }
   - LetterRevealReadyMessage: { type: 'letterRevealReady', myLetter, partnerLetter }

Handle SignalR gracefully when not configured (check getSignalRService() return).
  </action>

      - Returns { success: true, data: LetterState }
      - 404 if prompt not found

   b) PUT /api/letters/:envelopeId (auth required):
      - Saves letter content (for auto-save)
      - Body: { content: string, photoUrl: string | null }
      - Validate with Zod: content max 5000 chars
      - Calls saveLetter service
      - Returns { success: true, data: Letter }

   c) POST /api/letters/:envelopeId/submit (auth required):
      - Submits letter (marks as complete)
      - Calls submitLetter service
      - Returns { success: true, data: { revealed, letters? } }

   Admin routes:

   d) POST /api/letters/prompt (admin required):
      - Creates new letter prompt
      - Body: { envelopeId, prompt }
      - Validate with Zod
      - Returns { success: true, data: LetterPrompt }

   e) PATCH /api/letters/prompt/:id (admin required):
      - Updates prompt text
      - Body: { prompt }
      - Returns { success: true, data: LetterPrompt }

   f) DELETE /api/letters/prompt/:id (admin required):
      - Deletes prompt (cascades to letters)
      - Returns { success: true, data: {} }

2. Register routes in server/src/index.ts:
   - Import letterRouter from './routes/letter.js'
