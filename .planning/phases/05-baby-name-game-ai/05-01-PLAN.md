<task type="auto">
  <name>Task 1: Database schema and migration</name>
  <files>server/prisma/schema.prisma</files>
  <action>
Add three new Prisma models to the schema following the exact patterns from WyrPrompt/WyrVote:

**NameGameRound** — one per "Start Round" button press:
- `id` String @id @default(uuid())
- `envelopeId` String @map("envelope_id")
- `roundNumber` Int @map("round_number")
- `guidance` String? (null for first round, user's free-text for subsequent rounds)
- `createdAt` DateTime @default(now()) @map("created_at")
- Relation: `envelope Envelope @relation(fields: [envelopeId], references: [id], onDelete: Cascade)`
- Relation: `names NameGameName[]`
- @@unique([envelopeId, roundNumber])
- @@index([envelopeId])
- @@map("name_game_rounds")

**NameGameName** — individual generated name within a round:
- `id` String @id @default(uuid())
- `roundId` String @map("round_id")
- `name` String
- `origin` String[] (PostgreSQL text array for multiple origins)
- `meaning` String
- `notes` String
- `sortOrder` Int @default(0) @map("sort_order")
- `createdAt` DateTime @default(now()) @map("created_at")
- Relation: `round NameGameRound @relation(fields: [roundId], references: [id], onDelete: Cascade)`
- Relation: `votes NameGameVote[]`
- @@index([roundId])
- @@map("name_game_names")

**NameGameVote** — one vote per participant per name:
- `id` String @id @default(uuid())
- `nameId` String @map("name_id")
- `participantId` String @map("participant_id")
- `choice` String (values: 'love', 'maybe', 'nope')
- `createdAt` DateTime @default(now()) @map("created_at")
- Relation: `name NameGameName @relation(fields: [nameId], references: [id], onDelete: Cascade)`
- Relation: `participant Participant @relation(fields: [participantId], references: [id])`
- @@unique([nameId, participantId])
- @@index([participantId])
- @@map("name_game_votes")

**Update existing models:**
- Add `nameGameRounds NameGameRound[]` to Envelope model
- Add `nameGameVotes NameGameVote[]` to Participant model

- `NameGameRoundResponse` — roundId, roundNumber, names (NameVoteState[]), allVoted (boolean)
- `NameGameResults` — matches (GeneratedName[]), nearMisses (GeneratedName[]), worthDiscussing (GeneratedName[]), myVotes (Record<string, NameVoteChoice>), partnerVotes (Record<string, NameVoteChoice>)

- `NameGameStateResponse` — currentRound (NameGameRoundResponse | null), allMatches (GeneratedName[]), roundCount (number)

Zod schemas for request validation:
- `GenerateNamesRequest` — z.object({ guidance: z.string().max(500).optional() })
- `SubmitVoteRequest` — z.object({ choice: z.enum(['love', 'maybe', 'nope']) })

SignalR message types:
- `NameVoteSubmittedMessage` — type: 'name_vote_submitted', roundId, participantId, namesVotedCount, totalNames
- `NameRoundCompleteMessage` — type: 'name_round_complete', roundId, results (NameGameResults)

**Create `server/src/services/anthropic.ts`:**

Isolated AI wrapper service. Never called from routes directly — only from `nameGame.ts` service.

Key implementation details:
- Create `Anthropic` client instance with `apiKey: process.env.ANTHROPIC_API_KEY`
- Export `generateNames(params: GenerateNamesParams): Promise<AINameResponse>`
  - `GenerateNamesParams`: count (number), excludeNames (string[]), userGuidance (string | undefined)
  - `AINameResponse`: z.infer of the name response schema
- Use `output_config.format` with `type: 'json_schema'` for structured outputs (GA, no beta header needed)
- JSON schema: object with `names` array, each item has `name` (string), `origin` (array of strings), `meaning` (string), `notes` (string). All required, no additionalProperties.
- Model: `process.env.ANTHROPIC_MODEL ?? 'claude-sonnet-4-5-20250929'`
- `max_tokens: 2048`
- System prompt follows the locked contract from `docs/babymoon_portal_feature_blueprint.md` Section 10:
  - Neutral baby name ideation assistant
  - No ranking/scoring/prioritization
  - Neutral factual tone
  - Names as discussion starters only
  - All name types allowed (common, rare, traditional, modern)
  - Conservative on debated origins
  - Return fewer names rather than violate constraints
  - No apologies/explanations/meta-commentary
- User prompt: base context about diverse cultural origins + cross-cultural usability + concise factual notes, count, exclusion list (if any), user guidance (if any)
- Parse response: `response.content[0].text` -> `JSON.parse` -> Zod validate
- Graceful error handling: if ANTHROPIC_API_KEY is missing, throw with clear message mentioning the env var
