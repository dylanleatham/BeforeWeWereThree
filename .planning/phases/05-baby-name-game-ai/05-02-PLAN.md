  <action>
**Create `server/src/db/queries/nameGame.ts`** following `db/queries/wyr.ts` pattern:

Query functions (all typed, no raw SQL in handlers):
- `getNameGameState(envelopeId, participantId)` — Get current round with names and vote states. Returns null if no rounds exist. For each name: include myVote (from this participant) and partnerVoted (boolean, whether any other participant voted on this name). Use Prisma includes for votes relation.
- `getExcludedNames(envelopeId)` — Get all name strings from all rounds for this envelope. Used to build exclusion list for Anthropic API. Returns `string[]`.
- `createRound(envelopeId, roundNumber, guidance?)` — Create a new NameGameRound. Returns the created round.
- `createNames(roundId, names[])` — Bulk create NameGameName records from AI response. Each name gets a sortOrder (0-indexed). Returns created names.
- `submitVote(nameId, participantId, choice)` — Create a NameGameVote. Use `create` (not upsert). The @@unique constraint prevents double votes.
- `getVoteCountForRound(roundId)` — Count how many distinct participants have voted on ALL names in a round. Use: count participants where their vote count equals total name count for the round. Returns number (0, 1, or 2).
- `getRoundResults(roundId)` — Get all names with all votes for a round. Used to compute matches/near-misses/worth-discussing.
- `getAccumulatedMatches(envelopeId)` — Get all names across all rounds where both participants voted 'love'. Join across NameGameVote grouped by nameId where count of 'love' votes >= 2.
- `getNextRoundNumber(envelopeId)` — Get max roundNumber + 1 for this envelope. Returns 1 if no rounds exist.

**Create `server/src/services/nameGame.ts`** following `services/wyr.ts` pattern:

Service functions:
- `getNameGameState(envelopeId, participantId)` — Orchestrates query to get current round state + accumulated matches. Returns `NameGameStateResponse`.
- `generateRound(envelopeId, participantId, guidance?)` — Full round generation flow:
  1. Get next round number
  2. Get excluded names from all previous rounds
  3. Call `generateNames()` from anthropic service (count: 10, excludeNames, guidance)
  4. Create round record in DB
  5. Create name records in DB from AI response
  6. Return the new round state
- `submitVote(nameId, participantId, choice, envelopeId)` — Vote submission with race condition prevention:
  1. Wrap in `db.$transaction` with `{ isolationLevel: 'Serializable' }` (same pattern as WYR)
  2. Create the vote record
  3. Check if round is complete (both participants voted on ALL names)
  4. If complete: compute results and broadcast `name_round_complete` via SignalR to group `activity:{envelopeId}`
  5. If not complete: broadcast `name_vote_submitted` with progress (namesVotedCount / totalNames) via SignalR to same group
  6. Return `{ allVoted, results? }`
- `getAccumulatedMatches(envelopeId)` — Returns accumulated matches across all rounds.

**Results computation** (in service, called when round is complete):
- matches: names where both participants voted 'love'
- nearMisses: names where one voted 'love' and other voted 'maybe'
- worthDiscussing: names where both voted 'maybe'
- myVotes: map of nameId -> choice for requesting participant
- partnerVotes: map of nameId -> choice for other participant

**SignalR group name:** `activity:{envelopeId}` (same pattern as WYR)

Import realtimeService from `./realtime.js` and use `sendToGroup()` for broadcasts.

<task type="auto">
  <name>Task 2: API routes and server wiring</name>
  <files>server/src/routes/nameGame.ts, server/src/index.ts</files>
  <action>
**Create `server/src/routes/nameGame.ts`** following `routes/wyr.ts` pattern:

All routes use `authMiddleware` (not adminMiddleware — guests need access).
Import Zod schemas from shared types for request validation.
Use `successResponse` and `errorResponse` from shared types.

Endpoints:
1. **GET /api/name-game/:envelopeId**
   - Returns current round state + accumulated matches
   - Calls `nameGameService.getNameGameState(envelopeId, participantId)`
   - participantId from `req.session.participantId`
   - Returns `successResponse(state)`
   - If envelope not found, return `errorResponse('ENVELOPE_NOT_FOUND', ...)`

2. **POST /api/name-game/:envelopeId/generate**
   - Body: `{ guidance?: string }` validated with `GenerateNamesRequest` Zod schema
   - Calls `nameGameService.generateRound(envelopeId, participantId, guidance)`
   - Returns `successResponse(round)`
   - Handle Anthropic API errors: if ANTHROPIC_API_KEY missing, return `errorResponse('SERVICE_UNAVAILABLE', 'AI name generation is not configured')`
   - Catch Anthropic API errors and return `errorResponse('SERVICE_UNAVAILABLE', 'Failed to generate names')`

3. **POST /api/name-game/:nameId/vote**
   - Body: `{ choice: 'love' | 'maybe' | 'nope' }` validated with `SubmitVoteRequest` Zod schema
   - Need envelopeId for SignalR group — look up via name -> round -> envelopeId, or pass as query param
   - Calls `nameGameService.submitVote(nameId, participantId, choice, envelopeId)`
   - Returns `successResponse(result)` where result includes `{ allVoted, results? }`
   - If already voted (unique constraint violation), return `errorResponse('ALREADY_VOTED', ...)`

4. **GET /api/name-game/:envelopeId/matches**
   - Returns accumulated matches across all rounds
   - Calls `nameGameService.getAccumulatedMatches(envelopeId)`
   - Returns `successResponse({ matches })`

Use Express 5 typed params: `Request<{ envelopeId: string }>` and `Request<{ nameId: string }>`.

**Update `server/src/index.ts`:**
- Import `nameGameRouter` from `./routes/nameGame.js`
- Add `app.use('/api/name-game', nameGameRouter);` alongside existing route mounts
