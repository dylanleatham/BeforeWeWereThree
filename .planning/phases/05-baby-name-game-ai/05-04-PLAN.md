**Create `client/src/hooks/useNameGame.ts`** following `useWouldYouRather.ts` pattern:

Phase state machine:
```
type NameGamePhase = 'loading' | 'new-round' | 'generating' | 'voting' | 'waiting' | 'results';
```

State:
- `phase`: NameGamePhase (starts as 'loading')
- `currentRound`: NameGameRoundResponse | null
- `currentNameIndex`: number (0-based, advances after each vote)
- `allMatches`: GeneratedName[] (accumulated across rounds)
- `results`: NameGameResults | null
- `roundCount`: number
- `error`: string | null

Hook parameters: `envelopeId: string`

**Initialization (useEffect on mount):**
1. Call `getNameGameState(envelopeId)`
2. If no rounds exist (roundCount === 0): set phase to 'new-round' (show first round start)
3. If current round exists and not allVoted: set phase to 'voting' (resume voting)
4. If current round exists and allVoted: set phase to 'results'
5. Set allMatches from response

**Client-side name shuffling:**
- Names come from server in sortOrder. Client shuffles them using a deterministic seed based on participantId.
- Use a simple seeded shuffle: hash participantId to number, use as Fisher-Yates seed.
- This ensures each partner sees different order, but order is stable across refreshes.
- Get participantId from session (via useSession or similar).

**Actions:**
- `startRound(guidance?: string)`:
  1. Set phase to 'generating'
  2. Call `generateNameGameRound(envelopeId, guidance)`
  3. On success: shuffle names, set currentRound, set currentNameIndex to 0, set phase to 'voting'
  4. On error: set error, set phase to 'new-round'

- `vote(choice: NameVoteChoice)`:
  1. Optimistic: advance currentNameIndex
  2. Call `submitNameVote(nameId, choice)`
  3. If this was the last name (currentNameIndex >= names.length - 1):
     - If `allVoted` in response: set results, set phase to 'results'
     - Else: set phase to 'waiting'
  4. On error: rollback currentNameIndex, show error

- `startNewRound()`:
  1. Set phase to 'new-round'
  2. Clear results

**SignalR event subscriptions (useSignalREvent from existing hook):**
- Join group `activity:{envelopeId}` on mount, leave on unmount (useEffect pattern from WYR)
- `nameVoteSubmitted` event: update partner progress indicator (optional UI enhancement)
- `nameRoundComplete` event: set results from message payload, set phase to 'results', update allMatches

**Important patterns from CLAUDE.md:**
- Use ref pattern for event handlers to avoid stale closures
- Activities must work offline (don't block UI if SignalR unavailable)
- Capture values before async calls (e.g., capture nameId before awaiting submitNameVote)

Return: `{ phase, currentRound, currentNameIndex, allMatches, results, roundCount, error, startRound, vote, startNewRound }`
