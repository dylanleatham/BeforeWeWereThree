  <name>Task 1: Admin API functions and GenderRevealContentTab</name>
  <files>

  <action>
    1. **Add admin API client functions** to `client/src/services/api.ts`:
    - `getGenderRevealAdminConfig(envelopeId: string)`: GET /api/gender-reveal/admin/:envelopeId, returns GenderRevealAdminResponse
    - `configureGenderReveal(envelopeId: string, data: ConfigureGenderRevealRequest)`: POST /api/gender-reveal/admin/:envelopeId/configure, returns GenderRevealAdminResponse
    - `resealGenderReveal(envelopeId: string)`: POST /api/gender-reveal/admin/:envelopeId/re-seal
    - `deleteGenderRevealConfig(envelopeId: string)`: DELETE /api/gender-reveal/admin/:envelopeId

    2. **Create GenderRevealContentTab.tsx**:
    Follow WyrContentTab pattern for structure.

    State:
    - `selectedEnvelopeId: string | null`
    - `config: GenderRevealAdminResponse | null`
    - `isLoading: boolean`
    - `isSaving: boolean`
    - `isEditing: boolean` (show form vs display)
    - `formData: { genderValue: 'boy' | 'girl', keyA: string, keyB: string }`
    - `confirmAction: 'reseal' | 'delete' | null` (for confirmation dialogs)

    Layout:
    - **Heading**: "Gender Reveal Configuration" (from strings)
    - **Envelope selector**: Dropdown of envelopes filtered by `type === 'gender-reveal'`. Accept envelopes prop or fetch from existing getEnvelopes API. Show "Select a Gender Reveal envelope to configure" when none selected.

    When envelope selected, fetch admin config:
    - **If not configured** (config.configured === false):
      - Status badge: "Not configured" in muted color
      - Show form to create config
    - **If configured but not revealed** (config.configured === true, !config.revealedAt):
      - Status badge: "Configured — awaiting keys" in warm gold
      - Display: Gender value (Boy/Girl), Key A, Key B (visible to admin), validation state
      - Buttons: "Edit" (opens form with pre-filled values), "Re-seal" (if any key validated), "Delete Configuration"
    - **If revealed** (config.revealedAt set):
      - Status badge: "Revealed" with revealed date in warm green
      - Display: Gender value, revealed date, both keys shown
      - Buttons: "Re-seal Reveal" (reset to re-test), "Delete Configuration"

    **Config form** (used for both create and edit):
    - Gender radio buttons: Boy / Girl (styled as warm-toned toggle cards, not stark radio buttons)
    - Key A input: text, minLength 6, maxLength 8, alphanumeric validation, label from strings
    - Key B input: same
    - Hint text below each key input: "6-8 alphanumeric characters"
    - Validation: keys must be different (show inline error)
    - Save button, Cancel button (cancel returns to display mode)
    - On save: call configureGenderReveal, refresh config display

    **Re-seal confirmation**: Show confirmation message from REVEAL_ADMIN_RESEAL_CONFIRM. Confirm/Cancel buttons. On confirm: call resealGenderReveal, refresh config.

    **Delete confirmation**: Show confirmation message from REVEAL_ADMIN_DELETE_CONFIRM. Confirm/Cancel buttons. On confirm: call deleteGenderRevealConfig, clear config state.

    **IMPORTANT: Keys are shown on screen only.** Admin sees both keys in plain text. The app does NOT send keys to participants — admin shares them however they choose (text, whisper, physical card). This is by design per CONTEXT.md.

    CSS (GenderRevealContentTab.css):
    - Follow same class naming pattern as other content tabs
    - `.gender-reveal-tab` container
    - `.gender-reveal-tab__status` badge styling (not-configured: muted, configured: gold, revealed: sage)
    - `.gender-reveal-tab__config-display` card showing current config
    - `.gender-reveal-tab__key-display` monospace font for key values, slight background highlight so they stand out
    - `.gender-reveal-tab__form` form layout
    - `.gender-reveal-tab__gender-toggle` styled radio group for boy/girl selection
    - `.gender-reveal-tab__confirm` confirmation dialog styling
    - Standard admin styling patterns: warm sand background, dusk rose accents
